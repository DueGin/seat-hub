# 账号体系与 API Key 账号范围（v0.7.0 起）

本文是 v0.7.0「回到一个门面用户对应一个 vm2api 用户」的约定，实现以此为准。v0.4.0–v0.6.0 用的「单一服务账号 + 每用户账号池」方案已废弃，升级时自动迁回（见「从服务账号模式迁回」）。

## 账号体系

需要 vm2api v1.4.041 或更新版本（按属主限制密钥管理）。门面用 Master 管用户、号、账号池和用量，Master 只能管理**无归属**的密钥。租户密钥用该用户的 `/api/panel/login` 会话管理，不传 `user_id`，创建后核对返回的属主。会话仅缓存在内存；失效时重登。已登记的用户凭据缺失或失效时，门面用 Master 重设随机密码并加密保存；不会重设外部用户的密码。

- 门面有自己的用户体系（注册、登录、订单、工单都在门面）。
- **每个门面用户对应一个 vm2api 用户**（role=`user`，`vm_create_quota=0`），第一次需要时创建（第一次建密钥、第一次分配租赁号、第一次建托管槽），之后复用。
  - 用户名 `portal_<门面用户 id>`；该名字已被不是门面创建的 vm2api 用户占用时，改用 `portal_<id>_<4 位随机十六进制>`。
  - 密码随机生成，AES-GCM 加密存 `users.vm2api_password_enc`；id、用户名存 `users.vm2api_user_id` / `users.vm2api_username`。
- **vm2api 用户对门面用户不可见**：门面用户能看到的任何接口、页面、邮件、错误信息里都不出现 vm2api 用户名、用户 id、密码、上游密钥（`sk-vm-…`）或上游密钥 id。只有管理员在「用户管理」详情里能看到 vm2api 用户名和 id。
- 门面用户停用 → 对应 vm2api 用户停用，其上游密钥失去认证资格。已停用的 vm2api 用户无法登录，不会为了对账而临时启用；剩余密钥同步在重新启用后补做（用户自己停用的密钥保持停用）。
- 删除门面用户 → 先删除其可访问的上游密钥，再停用 vm2api 用户，**不删除用户**（删除会把 `admin_assigned` 槽收回平台池）。已停用用户的成员密钥无法访问，保留停用状态，不临时启用。

## 调度与隔离（同 v0.3.0）

- 租赁号、托管槽分配给租户 = `PATCH /api/panel/vms/:id/owner {user_id: <该用户的 vm2api 用户>}`。
- vm2api 只把用户的密钥调度到 `owner_user_id` 等于该用户的号（`ownerScopeFromApiKey` → `vmMatchesOwnerScope`），所以不同门面用户之间天然隔离；Master key 和管理员的密钥只能调度无归属的号。
- 回收：先 `SetSchedulable(false)`，再托管 `DeleteVM`、租赁 `SetVMOwner(nil)` 交还平台池。
- 不再使用 vm2api 账号池（`vm_pool_id` 永远为空）。

## API Key 账号范围（保留 v0.4.0 的用户功能）

| 模式 | `api_keys.scope_mode` | 上游 |
|---|---|---|
| 全部账号（默认） | `all` | `group_type=all`，不设白名单 —— 靠归属隔离，只能调到该用户名下的号 |
| 指定账号 | `selected` | `group_type=anthropic` + `allowed_vms` = 勾选的号 ∩ 可调度的号 |

- `vm2api.KeyScope` 增加显式的「全部」模式（`KeyScope{All: true}`）；零值仍然非法，必须三选一（All / AllowedVMs / PoolID，门面不再用 PoolID）。
- 「可调度的号」= 该用户 `status IN ('active','needs_reauth','suspended')` 且有 `vm_id` 的资源。向 vm2api 写白名单时还会检查实时归属；租户会话不能把别人的号加入白名单。
- 指定模式下勾选的号全部不可调度时：上游密钥**停用**，白名单保持原样（号被收回、转租给别人后归属已变，归属隔离保证调不到）；网关以 `key_no_accounts` 拒绝；重新勾选后恢复。
- 上游密钥是否启用 = 门面密钥 active **且** 门面用户 active **且** 范围可用。
- `api_keys.upstream_owner` 表示该上游密钥所属的 vm2api 用户 id。

## 从服务账号模式迁回（`owner_migrate`：启动时执行一次，之后每次对账也会执行，幂等）

对每个有未删除密钥、未释放资源或 `users.vm2api_pool_id` 的门面用户：

1. **确保该用户的 vm2api 用户**：`vm2api_user_id` 有值直接用；否则 `vm2api_username` 有值（之前门面建过，迁走时被停用、id 被清空）→ 在 vm2api 用户列表里按用户名找到它，启用并保存 id；都没有就按上面的规则新建。
2. **号归属**：该用户未释放资源的号，当前归属是服务账号或为空 → 改为该用户的 vm2api 用户；归属是**别的 vm2api 用户**（管理员手动改过）→ **不动**，记一条警告。
3. **密钥**：每个未删除的门面密钥，若租户会话看不到其上游密钥，或该密钥仍绑旧池 → 在该用户下新建上游密钥，替换 `vm2api_key_id` / `vm2api_secret_enc` / `upstream_owner`，旧 id 追加到 `previous_vm2api_key_ids`（用量历史不丢）。新密钥没有可保留的旧白名单时，指定范围如不可用，先停用再保存，待选到可用账号后写白名单并启用。用旧服务账号会话删除其名下且有门面引用的密钥；用 Master 删除有门面引用的无归属旧密钥。404 也可能表示不属于当前身份，不以此认定密钥不存在。若在另一门面用户会话中发现有门面引用的旧密钥，记 `key_drifted`，不修改它。用户手里的 `sk-pt-` 密钥不变。
4. **账号池**：删除 `users.vm2api_pool_id` 指向的池（404 忽略），清空该列；池仍被别的密钥引用（409 `vm_pool_in_use`）→ 清空该列、保留池，记录其 id 供后续对账重试和重新生成警告。
5. 全部用户处理完后：服务账号名下没有密钥、也不拥有任何号 → 停用服务账号（不删除，`settings.vm2api_service` 保留）。

任何一步失败只影响该用户，下次对账重试；用户的 `sk-pt-` 密钥在整个过程中一直有效（中间可能有几秒调用失败）。

## 对账（每 10 分钟，`owner_reconcile`；管理后台「立即重新检查」可马上触发）

1. 先跑一遍迁回（上一节），处理上次没完成的。
2. 对每个有密钥或资源的门面用户：vm2api 用户启用状态与门面用户一致；每个未删除密钥上游存在（不存在就按第 3 步重建）、范围 / 启用 / 并发与门面一致。
3. 未释放资源的号：归属为空或是服务账号 → 改回该用户；归属是别的 vm2api 用户 → **不抢回**，记警告。
4. 门面创建的 vm2api 用户名下、门面不认识的上游密钥 → 停用（不删除）。
5. 门面 vm2api 用户之外的用户、密钥、号（例如管理员在 vm2api 手动建的用户）一律不碰。

## 租赁池保护

- 分配租赁号前先确认该号在 vm2api 里**没有归属**；已归属别人（例如管理员在 vm2api 里把它分给了某个用户）→ 跳过，换下一个号，并记警告；全部不可用时按缺货处理。
- vm2api 的归属更新不支持条件写入；请勿在 vm2api 面板中同时改动门面正在分配或回收的租赁号。
- 这种号不计入可售库存；租赁池列表里标出「已被 vm2api 用户 X 占用」。
- 入池（`RentalAdd`）原本就要求无归属，不变。

## 管理后台「需要处理的问题」

`GET /api/admin/dashboard` 的 `scope_warnings`：`{checked_at, items:[{kind, user_id?, user_email?, vm_id?, key_id?, message}]}`，每次对账整体重算，处理好后自动消失。`kind`：

| kind | 含义 |
|---|---|
| `vm_owner_conflict` | 门面用户正在用的号，在 vm2api 里归属了别的用户 |
| `rental_vm_taken` | 租赁池里可分配的号，在 vm2api 里已归属别的用户 |
| `key_drifted` | 确认门面引用的旧密钥归属另一门面管理的 vm2api 用户，未修改；vm2api 不允许门面检查外部用户的密钥 |
| `pool_in_use` | 旧账号池仍被别的密钥引用，未删除 |

`POST /api/admin/scope/recheck` 保留，触发一次 `owner_reconcile`。

## 用量

继续按用户的上游密钥（当前 + `previous_vm2api_key_ids`）汇总，服务账号模式期间的历史不丢。单个号的用量：号当前归属必须是该用户的 vm2api 用户（迁回前的历史资源也接受服务账号），时间限定在租期内，只计该用户密钥的请求。
